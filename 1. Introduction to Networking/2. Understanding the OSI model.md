## مدل **OSI** یکی از مهم‌ترین مفاهیم در شبکه‌ است و لایه های مختلفی دارد که هر کدام را به صورت جداگانه توضیح میدهم :

### 🤔 یعنی چی Data encapsulation ؟

برای فهم مدل **OSI**، اول باید بفهمید **data encapsulation** چیه. به عنوان مثال ، فرض کن می خواهید به یک دوست که توی شهر دیگه‌ای زندگی می‌کند یه نامه بفرستید حالا اگه نامه رو بدون پاکت بفرستید، بدون هیچ اطلاعاتی مثل اسم و آدرس و کدپستی فرستنده و گیرنده یا اگه فقط نامه رو بنویسید و بندازید توی صندوق پستی چه اتفاقی رخ میدهد ؟
بیاید دو تا مثال زیر را با هم بررسی کنیم: یه نامه بدون پاکت (سمت چپ) و یه نامه که داخل پاکت گذاشته شده و تمام اطلاعات مورد نیاز آدرس مقصد روش نوشته شده (سمت راست). اگه این دو تا را بندازید تو صندوق پست، کدوم یکی به دست گیرنده می‌رسد و کدام نمی‌رسد؟

کاملاً مشخصه ، اگه یک نامه رو بدون پاکت و بدون هیچ اطلاعات اضافه‌ ای مثل مشخصات فرستنده و گیرنده بفرستید، اداره پست نمی‌داند باید آن را به کجا تحویل بده. نامه به دست هیچ‌کس نمی‌رسد. برای اینکه مطمئن بشید اطلاعات (همون نامه) به دست گیرنده درست می‌رسه، باید اطلاعات اضافه‌ای رو همراه نامه قرار بدیم تا اداره پست بدونه چطور باید باهاش رفتار کنه در واقع ما data رو encapsulate می‌کنیم .

<img width="1121" height="445" alt="Screenshot 2026-06-08 162929" src="https://github.com/user-attachments/assets/48536f74-93cb-409f-ace0-d6c3fe5c0e3b" />


پاکتی که نامه رو encapsulate می‌کنه شامل اطلاعات زیر می‌شه که به اداره پست کمک می‌کنه نامه رو درست تحویل بده:
- تمبر و کارت‌پستال
- اسم فرستنده
- آدرس فرستنده
- کد پستی فرستنده
- اسم گیرنده
- آدرس گیرنده
- کد پستی گیرنده

ایده اصلی اینه که فرستادن نامه دقیقاً مثل فرستادن اطلاعات با استفاده از اداره پست به‌ عنوان یک medium هستش. تو شبکه‌های کامپیوتری وقتی میگنmedium  منظور **راه انتقال داده** بین دو نقطه است. اداره پست خودش اطلاعات رو نمی‌فهمه، فقط بسته‌ها رو جابه‌جا می‌کنه. یعنی نقشش اینه که نامه یا بسته رو از فرستنده بگیره و از یک مسیر حمل‌ ونقل (ماشین، هواپیما، پستچی) به گیرنده برسونه در نتیجه اداره پست میشه یک بستر انتقال (medium)  برای پیام فیزیکی .
فرستادن ایمیل هم دقیقاً همینه بازم پروسه ارسال اطلاعاته، اما از طریق یک Network کامپیوتری. نکته کلیدی اینه که تو هر دو حالت، نمی‌تونید فقط خود اطلاعات رو به ‌تنهایی بفرستید؛ باید یه سری جزئیات اضافه هم همراهش باشه تا به medium انتقال ‌دهنده بگه چطور اطلاعات رو deliver کنه.

### حالا Data Encapsulation  در Networking چیه ؟
شبکه‌های کامپیوتری هم تقریباً شبیه اداره پست کار می‌کنن. فرقش اینه که به‌جای نامه‌های کاغذی، اطلاعات دیجیتال رو جابه‌جا می‌کنن. اما همون‌طور که نمی‌تونید یه نامه ساده رو همین‌طوری بندازید تو صندوق پست و انتظار داشته باشید به دست گیرنده برسه، تو شبکه هم نمی‌تونید raw data رو همین‌طوری بفرستید و توقع داشته باشید به destination برسه. 
- داده خام ( raw data ) : اطلاعات خامی که می‌خوای بفرستی 
- مقصد ( destination ) : یعنی مقصد ، جایی که داده باید برسه.

همون‌طور که تو دیاگرام زیر می‌بینید، اول باید data رو با یه سری اطلاعات اضافه encapsulate کنید.

<img width="1123" height="518" alt="Screenshot 2026-06-08 164526" src="https://github.com/user-attachments/assets/afd9ef01-a616-48fe-9f04-f17797d20a6c" />


فرض کنید یه دستگاه مثل لپتاپ می‌خواد data رو روی network بفرسته. مثلاً می‌خواهید تو فیسبوک برای یکی از دوستاتون پیام بفرستید. وقتی پیام رو تایپ می‌کنید و اینتر رو می‌زنید، data  از web browser (جایی که فیسبوک رو باز کردید)، میره سمت  Operating System (OS)، بعد به  NIC و در نهایت وارد network می‌شه. خیلی از پروسه‌ها اطلاعات اضافه خودشون رو بهش می‌چسبونن که بهشون headers می‌گن. این  headerها شامل جزئیات مهمی می‌شوند مثل:
•	این data برای کیه.
•	از کجا اومده؟
•	چطوری باید deliver بشه.
•	چه نوع data ایه؟

در نهایت، همون پیام ساده فیسبوکیِ "Hey! What's up?" شبیه یه network packet می‌شه که با چند تا header مختلف encapsulate شده، همون‌طور که تو دیاگرام زیر می‌بینید.

<img width="1122" height="497" alt="Screenshot 2026-06-08 165551" src="https://github.com/user-attachments/assets/e1dd45c1-93cd-47a9-932e-e7683266a08f" />


این اطلاعات اضافه به  network deviceها مثل router و switch کمک می‌کنه بفهمن چطور باید با data رفتار کنن و اون رو درست forward کنن تا به دست گیرنده اصلیش یعنی یکی از سرورهای فیسبوک برسه. در واقع Encapsulation همون پروسه اضافه کردن اطلاعات بیشتر به data یا همون payload هست تا network device ها بفهمن این پیام رو دقیقاً کجا باید deliver کنن. وقتی data به destination می‌رسه، دقیقاً پروسه برعکس رو طی می‌کنه ، یعنی قبل از اینکه تحویل application مربوطه بشه، این  headerها یکی‌ یکی از روش برداشته می‌شن.

### حالا NIC (Network Interface Card) کارش چیه ؟ 
یعنی کارت یا سخت‌افزاری که کامپیوتر رو به شبکه وصل می‌کنه ، مثل **درگاه یا پل ارتباطی** بین کامپیوتر و شبکه است. بدون NIC، کامپیوتر نمی‌تونه به اینترنت وصل بشه و با دستگاه‌های دیگه شبکه حرف بزنه .
#### وظیفه NIC چیه؟
•	داده‌های کامپیوتر رو به سیگنال شبکه تبدیل می‌کنه .
•	داده‌های شبکه رو برای کامپیوتر قابل فهم می‌کنه .
•	به هر دستگاه یک MAC Address  میده .

### چرا به OSI model نیاز داریم؟
پروسه data encapsulation اصلاً ساده نیست. این پروسه شامل  protocols، headers  و مراحل مختلفی می‌شه. هر بخش از network مثل  applications، network device ها و physical mediumها باید بدونه که با data  چیکار کنه و چطور اون رو درست handle کنه. در روزای اول  networking، شرکت‌های مختلف سیستم‌های خودشون رو می‌ساختن و از روش‌های encapsulation خودشون استفاده می‌کردن.
این سیستم‌ها اغلب نمی‌تونستن با هم کار کنن چون از ruleهای یکسانی پیروی نمی‌کردن مثلاً، یه vendor ممکن بود یه سری header خاص رو با یک ترتیب Unique اضافه کنه که device یه vendor دیگه اصلاً نتونه اون رو درک کنه. این موضوع، ارسال data رو بین  networkهای مختلف یا حتی بین  deviceهای خود همون شرکت خیلی سخت می‌کرد.
علاوه بر این، برای رسیدن به سرعت‌های فوق‌العاده بالای  networkهای امروزی، network device ها باید دقیقاً همون اطلاعاتی رو که نیاز دارن پیدا کنن، بدون اینکه بخوان  header های نامربوط رو بررسی کنن، همون‌طور که تو دیاگرام زیر نشون داده شده.

<img width="1116" height="448" alt="image" src="https://github.com/user-attachments/assets/9d53b819-f9f4-45cc-a7bd-3da0f9ec9d95" />

 
برای حل این مشکل، مهندس‌ها فهمیدن که صنعت به یک **framework** استاندارد نیاز داره. اونا به یه روش مشترک نیاز داشتن تا مشخص کنن data چطور باید آماده، ارسال و دریافت بشه. اینجاست که پای OSI model میاد وسط. OSI model  یک ساختار مرحله ‌به ‌مرحله میده تا نشون بده data encapsulation چطور باید انجام بشه :
•	هر layer  وظیفه مشخصی داره، مثل اضافه کردن آدرس‌های source و destination یا بررسی errorها.
•	هر layer  از  protocol های خاصی استفاده می‌کنه که از ruleهای توافق ‌شده پیروی می‌کنن.
•	هر layer میاد header و بعضی وقتا trailer مخصوص خودش رو به پیام اضافه می‌ کنه، تا سیستم گیرنده بدونه چطور باید اون رو process کنه.
خلاصه اینکه، OSI model  با ارائه یه روش واضح و استاندارد که همه تو دنیای networking بتونن ازش استفاده کنن، کمک می‌کنه تا پیچیدگی data encapsulation رو مدیریت کنیم. این موضوع باعث تضمین interoperability، consistency  و راحت ‌تر شدن troubleshooting می‌شه. در واقع OSI model به ما کمک می‌کنه درک کنیم و توضیح بدیم که چطور data لایه ‌به ‌لایه بسته ‌بندی می‌شه (encapsulation) و چطور اون طرف تو مقصد باز می‌شه (de-encapsulation) .

## حالا **OSI model** چیه؟ 
مدل  OSI، یا همون  Open Systems Interconnection model، یه framework هست که پروسه encapsulation  رو به هفت تا layer تقسیم می‌کنه. هر layer نقش مشخصی داره و یه بخش از encapsulation رو هندل می‌کنه، چیزایی مثل  data formatting، logical addressing، routing، physical addressing  یا error checking.
مثال زیر نشون می‌ده که data چطور از بین  layerهای OSI عبور می‌کنه و تو هر مرحله، قبل از اینکه روی network  به سمت device بعدی فرستاده بشه، چطور wrap می‌شه. دقت کنید که هر layer میاد header مخصوص خودش رو با اطلاعات مربوط به اون network function بهش اضافه می‌کنه.

<img width="741" height="547" alt="image" src="https://github.com/user-attachments/assets/095ce23b-bcbc-4601-8c3f-a23bee6e58ff" />


هدف اصلی OSI model اینه که یک framework  استاندارد و vendor-agnostic برای data encapsulation ایجاد کنه. این مدل کمک می‌کنه تا deviceها و سیستم‌های مختلف با پیروی از یه مجموعه rule و استاندارد یکسان، بتونن با هم کار کنن.
دیاگرام زیر هر layer رو با یه توضیح خلاصه و  protocolهایی که تو اون layer کار می‌کنن، نشون میده. دقت کنید که به ‌طور کلی، network device های مختلف تو layerهای متفاوتی از OSI model کار می‌کنن. این یعنی یک network device  فقط به  headerها تا یک layer خاص اهمیت میده و کاری به بقیه  headerهای موجود تو پیام نداره. مثلاً، یه switch فقط به header لایه data link در layer 2 کار داره، که شامل  MAC addressهای source  و destination می‌شه. یک router فقط به  headerهای layer 2 و layer 3 اهمیت میده، و همین‌طور تا آخر.

### مقایسه OSI model و  TCP/IP model
مدل OSI با 7 تا layer خودش، یه روش ساختاریافته و کاربردی برای درک نحوه کار data encapsulation هست. اما مهندسای شبکه خیلی زود متوجه می‌شن که layerهای 5 ، 6 و ۷ ربط مستقیمی به اکثر  networking taskها ندارن. این layerها بیشتر تمرکزشون روی اینه که  software applicationها چطور data رو هندل می‌کنن، که معمولاً خارج از scope شبکه است.
در نتیجه، متخصصای شبکه از طریق کار عملی و تجربه‌های دنیای واقعی، شروع کردن به استفاده از یه مدل ساده ‌تر که روی بخش‌هایی تمرکز داره که برای شبکه بیشترین اهمیت رو دارن یعنی Layer 1 تا Layer 4 . این موضوع باعث توسعه TCP/IP model شد که layerهای کمتری داره و خیلی بیشتر با نحوه کارکرد واقعی  networkها تطابق داره.
دیاگرام زیر مقایسه‌ای بین OSI model با 7 تا  layer، نسخه اولیه TCP/IP که 4 تا layer داشت و نسخه مدرن TCP/IP model با 5 تا layer رو نشون میده.
